# 사후 측정: 지금 검색 방식으로 주식 관련 기사가 잘 나오는가

- 측정일: 2026-11-19 오전(10:08 에 운영 서버 공개 API 에서 내려받은 자료).
- 성격: **검색 방식을 정한 뒤에 한 확인**이다. 검색 방식을 고를 때 다른 방식과 비교한 적은 없다.
- 분류 원자료: `2026-11-19-news-query-relevance-labels.tsv` (150건, 두 분류 결과 포함).

## 지금 검색 방식

`NewsService` 가 종목마다 네이버 뉴스 검색 API 를 한 번 부른다.

| 항목 | 값 |
|---|---|
| 검색어 | 종목명을 큰따옴표로 감싼 문자열(`"삼성전자"`). 코드 주석의 의도는 "정확히 일치 검색"이다. 네이버 API 가 큰따옴표를 실제로 정확 일치로 처리하는지는 문서로 확인하지 않았다 |
| 정렬 | 관련도순(`sort=sim`) |
| 받는 건수 | 30건 |
| 거르는 규칙 | 48시간 이내, 제목에 종목명이 독립된 단어로 있음, 중복 제거 |
| 쓰는 건수 | 종목당 최대 5건 |

## 무엇을 쟀나

1. **채움 정도**: 종목마다 5건이 채워지는가. 분류 없이 건수만 센다.
2. **관련성**: 뽑힌 기사가 그 종목 주식을 보는 사람에게 관련 있는 기사인가. 제목과 요약(앞 160자)을 읽고 분류한다.
3. **시세 자동 기사 비중**: "○○ 주가, 8월 14일 장중 26,600원 3.91% 상승" 형식의 제목을 정규식으로 센다.

자료는 두 가지다.

- **현재 수집분**: 2026-11-19 10:00 정기 실행(id 10)의 10종목 47건. 지금 코드 그대로의 결과다.
- **아카이브**: 2026-07-29 ~ 2026-09-23, 36거래일, 종목-일 315개, 기사 1,487건. 지금 코드보다 앞선 코드로 수집됐다. 2026-11-18 변경(커밋 `85aecb46`) 직전 코드를 보면 검색어와 정렬은 지금과 같고(큰따옴표, `sort=sim`), 받는 건수는 20건이었으며, 중복 제거와 다른 회사 기사를 거르는 규칙(커밋 `d2f399fd`)은 없었다(`git show` 로 확인). 아카이브를 수집한 7~9월에 실제로 배포돼 있던 버전은 따로 확인하지 않았다.

## 결과 2. 관련성

### 분류 기준 (기사를 읽기 전에 정함)

예는 기준을 정할 때 적어 둔 가상의 제목이다(표본에서 고른 것이 아니다).

| 분류 | 뜻 | 예 |
|---|---|---|
| A 투자 관련 | 주가·수급·목표주가·실적·공시·수주·투자·인수합병·경영진 인사·사업 전략·제품과 기술의 사업적 의미·업황·규제·노사 | "삼성전자, 3분기 영업이익 12조…반도체 회복" |
| B 회사 소식이지만 투자 정보는 약함 | 사회공헌·행사·수상·순위·단순 홍보 | "현대차, 연말 이웃돕기 성금 기탁" |
| C 회사는 맞지만 주식과 무관 | 연예 활동·스포츠·부동산 등 다른 주제에 이름만 등장 | "하이브 소속 ○○, 신곡 뮤직비디오 공개" |
| D 다른 대상 | 이름은 같거나 포함되지만 다른 회사·상품 | 종목 `에스엠` 에 "에스엠벡셀" 기사 |

### 표본과 분류자

- 표본 150건 = 현재 수집분 47건 전부 + 아카이브 1,487건에서 무작위 103건(고정 시드).
- 150건을 섞어 번호만 붙인 뒤 **두 분류자가 서로의 결과를 보지 않고** 분류했다. 둘 다 AI 다(메인 세션 모델, 그리고 별도로 띄운 Sonnet). 사람이 검토하지는 않았다.

### 두 분류의 일치

| 항목 | 값 |
|---|---|
| 일치 | 145 / 150 (96.7%) |
| 코헨 카파 | 0.81 |
| 불일치 5건 | A↔B 4건, B↔C 1건 |

불일치는 모두 경계 사례였다(협력사 기사에 거래처로 등장, 디자인 전략 소개, 모터쇼 신차 공개, 임직원 대출과 집값).

### 분류 결과

아래는 **두 분류자가 모두 A 로 본 건수**로, 가장 엄격하게 센 값이다.

| 자료 | 건수 | 둘 다 A | 어느 한쪽이라도 C·D |
|---|---|---|---|
| 현재 수집분 | 47 | 44 (93.6%) | 0 |
| 아카이브 표본 | 103 | 90 (87.4%) | 2 |
| 합계 | 150 | 134 (89.3%) | 2 |

- A 가 아닌 16건 중 14건은 B 쪽(사회공헌, 브랜드평판 순위, 행사 참가, 협력사 기사)이었다.
- C·D 2건은 아카이브에서 나왔다. `카카오` 종목의 "카카오뱅크" 기사(지금은 다른 회사 기사로 걸러지는 형태)와, 삼성전자 임직원 대출이 동탄 집값에 주는 영향을 다룬 기사다.
- 엔터 종목(`에스엠`, `하이브`, `JYP Ent.`) 12건은 모두 주가·실적·인수 기사였다. 다만 이날은 엔터주가 급등한 다음 날이라 주가 기사가 많았다. 평소에 연예 활동 기사가 섞이는지는 이 표본으로 말할 수 없다.

## 결과 3. 시세 자동 기사 비중

| 자료 | 시세 자동 기사 형식 | 비율 |
|---|---|---|
| 현재 수집분 | 4 / 47 | 8.5% |
| 아카이브 전체 | 236 / 1,487 | 15.9% |

- 아카이브의 236건은 두 호스트에서만 나왔다(`www.topstarnews.net` 135건, `www.joongangenews.com` 101건).
- 종목별로는 `NAVER` 50건, `삼성전자우` 35건, `두산에너빌리티` 31건 순이었다.
- 이 기사들은 A(투자 관련)로 분류되지만 내용은 현재가와 등락률뿐이다. 관련성은 높아도 "왜 올랐는지"를 알려 주지 않는다. 종목당 5건 중 이런 기사가 차지하는 만큼 분석에 쓸 내용이 줄어든다.

## 정리

- 지금 방식으로 뽑힌 기사는 **표본 150건 중 약 89%가 주가·실적·사업 기사**였고, 종목과 무관하거나 다른 회사인 기사는 2건이었다.
- 약점은 관련성이 아니라 두 가지다. (1) 종목명 표기가 기사 제목과 다른 종목은 5건을 못 채운다. (2) 내용이 시세뿐인 자동 기사가 8~16% 들어온다.

## 한계

- 분류자는 둘 다 AI 이고 같은 회사 모델이다. 사람 검토는 없다. 제목과 요약 앞 160자만 봤다.
- 현재 수집분은 한 시점(10종목 47건)이다. 아카이브는 지금의 필터가 들어가기 전에 수집된 것이다.
- **다른 검색 방식과의 비교는 하지 않았다(미측정).** "종목명 + 주가"로 검색하거나 최신순으로 정렬했을 때 결과가 어떻게 달라지는지는 모른다. 측정하려면 네이버 검색 API 키가 필요한데 이 PC 에는 키가 없다.
- 채택되지 않은 기사(30건 중 나머지)는 저장하지 않으므로, 좋은 기사가 걸러졌는지는 확인하지 못했다.

## 이 측정 뒤에 한 일

- 종목명 표기가 제목과 다른 종목의 기사 부족에 대해 **종목 별칭 검색**을 구현했다(2026-11-19, 작업 폴더 기준·미배포). `NAVER` → 네이버, `JYP Ent.` → JYP엔터테인먼트·JYP엔터, `에스엠` → SM엔터테인먼트·SM엔터. 내용은 `docs/ARCHITECTURE_DECISIONS.md` 2번 절.
- 이 문서의 숫자는 모두 별칭 검색을 넣기 **전**의 값이다. 별칭을 넣은 뒤의 채움 정도와 관련성은 재지 않았다.
