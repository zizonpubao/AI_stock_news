# StockPulse 개선 기록 — 측정, 실험, 적용, 문제 해결

이 문서는 2026-11-18 에 진행한 개선 작업의 근거를 모은 것이다.
모든 수치는 직접 실행하거나 운영 데이터를 읽어 얻은 값이며, 확인하지 못한 것은 "미확인"으로 적었다.
공식 문서에서 가져온 사실에는 출처를 달았고, 그중 요약 도구를 거쳐 읽은 것은 그렇게 표시했다(발표 전 원문 대조 권장).

## 1. 실측: 기존 서비스는 실제로 어떤 상태였나

**방법.** 운영 DB 의 아카이브를 공개 조회 API(`/api/archive/...`)로 전부 내려받아 분석했다.
대상은 2026-07-29 ~ 2026-09-23 의 36거래일, 종목-일 315건이다.
"미리 써둔 문구"는 코드에 하드코딩돼 있던 문장(`📈 주요 이슈 / - 실적 개선 기대감으로 외국인 및 기관 순매수 유입 …`)과 앞부분이 일치하는지로 판정했다.

| 측정 항목 | 결과 |
|---|---|
| 미리 써둔 문구가 "AI 분석"으로 저장된 건 | 315건 중 217건 (68.9%) |
| 그날 전 종목이 미리 써둔 문구였던 날 | 36일 중 25일 |
| 전 종목이 실제 AI 분석이었던 날 | 36일 중 9일 |
| 한 종목만 미리 써둔 문구였던 날 (응답에서 그 종목만 빠짐) | 2일 |
| 예시 종목(삼성전자 75,000원 +5.63% 등 5개)이 저장된 날 | 9일 (2026-09-11 ~ 09-23), 종목-일 45건 |
| 실제 AI 분석 98건 중 뉴스가 0건이었던 것 | 3건 |
| 저장된 뉴스 1,484건 중 중복 (새 규칙으로 판정) | 20건 (1.3%), 영향받은 종목-일 306건 중 19건 (6.2%) |

**알게 된 것.**
- 가짜 데이터는 가정이 아니라 실제로 서비스되고 있었다.
- 2026-09-11 부터는 수집 대상인 네이버 금융 인기검색 페이지가 개편되어(4장 참고) 예시 종목이 9거래일 동안 저장됐다.
- 커밋 기록에는 2026-07-29 ~ 30 에 "재시도·모델 폴백으로 더미 분석 출력 문제 해결"이 있다. 그러나 그 뒤 34거래일 중 24일이 여전히 전부 미리 써둔 문구였다. **실패가 그럴듯한 문구에 가려져 있어, 고쳤는지 확인할 방법이 없었다.**
- 뉴스 중복은 예상보다 작았다(1.3%). 중복 제거는 적용했지만 핵심 문제는 아니었다. 대신 다른 종목이 주인공인 기사가 제목에 이름이 스쳤다는 이유로 들어가는 관련성 문제가 눈에 띄었다(미해결, 8장).

## 2. 원인 추적

| 현상 | 원인 | 확인 방법 |
|---|---|---|
| 수집 0건 → 예시 종목 저장 | `finance.naver.com/sise/lastsearch2.naver` 가 `stock.naver.com` 으로 302 리다이렉트되고, 새 페이지는 스크립트로 그려 HTML 에 표가 없음 | 직접 요청해 리다이렉트와 `<table>` 0개 확인 |
| AI 호출 실패가 잦음 | 폴백 목록의 `gemini-2.0-flash` 가 2026-06-01 종료된 모델. 폴백을 추가한 시점(07-30)에 이미 쓸 수 없었음 | Gemini 공식 종료 일정 문서 (요약 도구로 읽음) |
| 응답에서 한 종목만 빠짐 | 자유 텍스트를 `[종목N]` 태그로 잘라 쓰는 방식이 형식 오차에 약함 | 아카이브에서 2일 확인 |
| 실패를 몰랐음 | 실패 시 대체 문구·예시 종목을 저장하고, 실행 결과를 어디에도 남기지 않음 | 코드와 아카이브 |

첫 모델(`gemini-2.5-flash`)이 왜 그렇게 자주 실패했는지(과부하, 한도 등)는 당시 기록이 없어 **미확인**이다. 지금은 실행 이력이 남으므로 앞으로는 알 수 있다.

## 3. 적용한 개선 (데이터 흐름 순서)

### 3-1. 종목 수집
- **문제**: 원본 페이지 개편으로 수집 0건. 기존 코드는 이때 예시 종목을 저장.
- **조치**: 네이버 모바일 증권의 JSON 응답으로 수집 소스 교체. 실패하면 DB 를 건드리지 않고 직전 수집분 유지.
- **확인**: 같은 조건에서 원본과 수정본을 각각 실행해 비교(2026-11-18).

| 상황 | 원본 코드 | 수정 후 |
|---|---|---|
| 수집 소스 장애 시 화면 | 삼성전자 75,000원 +5.63% 등 예시 5종목 + 미리 써둔 "AI 분석" | 예시 없음, "최근 종목 수집에 실패했습니다" 안내 |
| 같은 시각 실제 삼성전자 | 189,800원 (-3.56%) | (수집 복구 후 실제 값 표시) |

- **한계**: 새 수집 주소는 네이버가 문서로 공개한 Open API 가 아니다. 구조가 바뀌면 빈 목록을 돌려주고 실패로 기록·표시한다.

### 3-2. 뉴스 수집
- 호출 실패를 "뉴스 없음"과 구분: 종목마다 `newsStatus`(성공/실패/대기) 저장, 화면에 "뉴스를 수집하지 못했습니다" 표시.
- 중복 기사 제거: 제목 정규화 + 숫자 일치 + 문자 2-gram 자카드 0.7 이상, 같은 링크. (숫자 일치 조건은 "1분기 영업이익 증가"와 "2분기 영업이익 증가"가 유사도 약 0.78 로 묶이는 것을 실행으로 확인하고 넣음)
- TLS 인증서 검증을 꺼두었던 코드 제거. JDK 기본 신뢰 저장소로 네이버 서버와 정상 연결됨을 확인.

### 3-3. AI 분석
- **뉴스가 있는 종목만 분석을 요청**한다. 없는 종목은 분석하지 않고 사유(`NO_NEWS`)를 남긴다. 근거 없이 추측한 분석을 만들지 않기 위함.
- **구조화 출력(JSON 스키마)** 으로 받고 코드에서 검증한다: 범위를 벗어난 근거 번호 제거, 근거 없는 이슈 제거, 응답에 빠진 종목은 `INVALID_RESPONSE`.
- **주요 이슈 문장마다 근거 기사 번호**를 붙인다. 관점·리스크는 "AI 해석"으로 구분 표기.
- 프롬프트 지침: 뉴스에 없는 수치·사실 금지, 뉴스 안의 지시문처럼 보이는 문장 무시, 매수·매도 권유와 목표 주가 금지.
- **실제 응답한 모델, 분석 시각, 뉴스 논조**를 종목마다 저장. 화면의 고정 문자열 "Gemini 2.5 Flash" 제거.
- 종료된 모델을 폴백 목록에서 제거.
- Gemini API 키를 URL 쿼리에서 요청 헤더로 이동. 원본은 호출 실패 로그에 키가 3회 남았고 수정본은 0회.
- **확인**: 운영 서버에서 실제 호출(2026-11-18 18:52) — 10종목 모두 성공, 근거 번호 부착, 모델 `gemini-2.5-flash`, 입력 5,850 / 출력 1,812 토큰, AI 분석 30.4초.

### 3-4. 화면
- 근거 번호 칩(누르면 해당 기사로 이동), 뉴스 목록 번호, 뉴스 논조 배지(주가 등락 색과 헷갈리지 않게 빨강·파랑 미사용).
- 분석 없음 사유를 구분해 안내: 근거 뉴스 없음 / AI 호출 실패 / 근거 확인 불가.
- 운영 현황 한 줄: 최근 24시간 수집 성공 횟수, AI 분석 성공 건수, 평균 분석 시간, 마지막 모델.
- 수집 실패 시 오래된 데이터를 최신처럼 보이게 두지 않음(날짜 표기, 실패 배너).

### 3-5. 운영
- 매 사이클의 결과를 `pipeline_run` 테이블에 기록: 트리거, 수집·뉴스·AI 결과, 모델, 토큰, 소요 시간, 결론(`OK` / `COLLECT_FAILED` / `NEWS_FAILED` / `AI_CALL_FAILED` / `PARTIAL` / `ERROR`).
- 조회: `GET /api/runs`, `GET /api/runs/summary` (공개, 읽기 전용).
- 관리용 API(`POST /api/stocks/refresh`, `POST /api/archive/run`, `/api/admin/**`)에 토큰 검사. 원본은 인증 없이 `POST /api/archive/run` 이 200 을 돌려주며 예시 종목 5개를 그날 아카이브로 저장했고, 수정본은 401.
- 오늘 수집분이 없으면 일일 아카이브를 건너뜀(며칠 전 데이터를 오늘 날짜로 저장하지 않도록).

## 4. 실험: 어떤 모델을 쓸 것인가

**배경.** 운영 모델 `gemini-2.5-flash` 는 지원 종료 예정이고, 2026-12-01 부터 요청이 `gemini-3.5-flash-lite` 로 자동 전환된다고 공식 문서에 안내돼 있다(요약 도구로 읽음: https://aistudio.google.com/docs/deprecations). 가만히 있어도 모델이 바뀌므로 미리 재보고 정한다.

**설계.**
- 입력: 운영 중인 실제 데이터(종목 10개, 기사 47건, 프롬프트 약 9,175자). 운영과 **같은 프롬프트·스키마·검증 로직**을 재사용.
- 모델당 3회 반복. 최대 출력 한도 16,000 으로 통일. 각 모델의 추론 설정은 기본값 그대로.
- 실행 위치: GitHub Actions. 실험용 SDK 는 운영 JAR 에 포함되지 않는다(운영 서버 메모리 1GB 보호).
- 가격: 각 사 공식 가격 페이지 확인값(2026-11-18, 요약 도구로 읽음). `backend/src/experiment/resources/model-prices.json` 에 출처와 함께 기록.

**지표.**
- 응답 시간(중앙값), 토큰, 1회 비용
- 형식 준수: 요청한 JSON 구조대로 왔는지, 어느 수준까지 형식을 강제할 수 있었는지
- 근거 유효율: 이슈 문장이 실제 존재하는 기사 번호를 가리키는 비율
- 수치 근거 일치율: 문장 속 숫자가 인용한 기사(제목+요약)에 실제로 있는 비율

실패 사유:
- `gemma-4-31b-it`: 1차 과부하(503) 2회와 한도 초과(429) 1회, 2차 타임아웃(90초) 1회.
- `gemini-2.5-flash-lite`: 6회 모두 404. 이 키로 호출 가능한 모델 목록에는 이름이 있는데 호출은 404 다. 원인 **미확인**.
- `gpt-6-luna`: 6회 모두 한도 초과(429). 실험 시점에 계정에 크레딧이 없었다. **미측정**.

형식: 성공한 모든 호출이 JSON 스키마 수준에서 받아들여졌다(Gemma 포함). 형식 문제로 한 단계 내려간 경우는 없었다.

수치 근거 불일치로 잡힌 예: 삼천당제약 이슈에서 "장중 10% 이상 급락"(Gemma), "장중 10%대 급락"(Claude Haiku). 인용한 기사에 "10%"라는 숫자 문자열이 없었다.

**읽을 수 있는 것.**
- 성공한 호출은 모두 형식을 지켰고 근거 번호가 실제 기사를 가리켰다.
- 응답 시간은 `gemini-3.5-flash-lite` 가 현재 운영 모델보다 약 3 ~ 5배 짧았다.
- 1회 비용은 `claude-haiku-5-5` 가 가장 낮았다(현재 운영 모델의 약 4분의 1).
- 현재 운영 모델은 출력 토큰의 약 65%가 내부 추론이었다(1차 평균 5,635 중 3,687).
- 무료 등급만 있는 Gemma 는 6회 중 2회만 성공했고 성공한 호출도 80초 이상 걸렸다.

**한계.** 모델당 3회, 한 시점의 입력 하나다. 통계적 유의성은 검증하지 않았다. 수치 근거 일치율은 숫자 문자열이 인용 기사에 있는지만 본다("2조"와 "20,000억"처럼 표기가 다르면 불일치로 잡히고, 맥락이 달라도 같은 숫자면 일치로 잡힌다). 응답 시간은 각 모델의 기본 추론 설정 기준이며 설정을 낮추면 달라질 수 있다.

**함께 검토했으나 실측하지 않은 후보** (공식 문서 조사만, 요약 도구로 읽음):

| 후보 | 최저가 모델 | 가격 | 메모 |
|---|---|---|---|
| Upstage Solar | `solar-mini4` | $0.10 / $0.40 | 국산. "유창한 한국어", API 로 보낸 데이터를 저장·재사용하지 않는다는 문구. 서버 위치 미확인 |
| 네이버 HyperCLOVA X | `HCX-007` 등 | 미확인 | 국산. 지원 리전 "한국". 가격·학습 정책 미확인 |
| DeepSeek | `deepseek-flash` | 시간대별 $0.15~0.30 / $0.60~1.20 | JSON 모드만 문서화. 데이터 정책 미확인 |
| xAI Grok | `grok-4.3` | $1.25 / $2.50 | 가격대가 10배 이상 |
| Groq | `openai/gpt-oss-20b` | $0.075 / $0.30 | 공개 모델 서빙 |

Gemma 는 Apache 2.0 라이선스의 공개 가중치 모델이라 자체 서버에 설치해 외부로 데이터를 보내지 않고 쓸 수 있다(공식 블로그). 다만 가장 큰 31B 모델은 양자화 수준에 따라 약 17.5 ~ 69.9GB 메모리가 필요하다고 안내돼 있어(gemma.ai) 현재 서버(1GB)에는 설치할 수 없다.

## 5. 개선 후 측정: 실행 이력

`GET /api/runs/summary?hours=24` 로 언제든 확인할 수 있다. 이 문서 작성 시점(2026-11-18 19:11)의 값:

| 항목 | 값 |
|---|---|
| 기록된 실행 | 2회 (배포 직후 1회, 19:00 정기 1회) |
| 수집 성공 | 2/2 |
| AI 분석 성공 | 20/20건 |
| 사용 모델 | `gemini-2.5-flash` |

표본이 아직 2회뿐이다. **발표 전에 위 주소를 다시 조회해 최신 값으로 바꿔야 한다.** 개선 전 기준선은 1장의 "36거래일 중 전 종목 실제 분석 9일"이다. 다만 기준선은 하루 한 번(16:05 아카이브 시점)의 상태이고 실행 이력은 매 사이클의 상태라서 단위가 다르다는 점을 함께 밝혀야 한다.

## 7. 문제 해결 기록

| 문제 | 원인 | 조치 | 확인 |
|---|---|---|---|
| 데모 백엔드 502 | EC2 사용 불가 | 네이버클라우드로 이전 | 공개 링크에서 실제 데이터 표시 |
| 수집 0건 | 네이버 금융 페이지 개편 | JSON 응답으로 수집 소스 교체 | 서버에서 10종목 수집 |
| 서버에서 빌드 불가 | 가용 메모리 405MB, 디스크 여유 1.9GB | 빌드를 CI 로 옮기고 서버는 실행만 | 자동 배포 성공 |
| 배포 키를 못 읽음 (`error in libcrypto`) | 웹 입력란에 여러 줄 키를 붙여넣는 과정에서 내용이 깨짐 | 키를 한 줄(base64)로 등록할 수 있게 하고, 키 형식을 먼저 검사해 원인을 알려주는 메시지 추가 | 전송 단계 통과 |
| 백엔드 기동 실패 | 서버 `.env` 에 예시 값(`your-db-user`)이 남아 DB 인증 실패 | 예시 값이 남은 항목을 값 노출 없이 찾는 명령으로 점검 후 수정 | `/api/health` UP |
| 8080 접속 불가 | 클라우드 방화벽 규칙 반영 전 | 응답 없음(방화벽이 버림)과 연결 거부(방화벽 통과, 프로그램 없음)를 구분해 원인 위치를 좁힘 | 연결 거부 → 기동 후 정상 |
| 디스크 93% | 배포마다 쌓인 빌드 캐시 | 캐시 정리, 워크플로에 정리 단계 추가 | 79% |
| 실험 결과표 값이 두 칸씩 밀림 | 머리글 14열, 값 12열 | 행에 누락된 두 칸 추가 | 재실행 결과 확인 |
| 뉴스 실패가 "뉴스 없음"으로 보임 | 예외를 잡고 빈 목록 반환 | 상태값으로 구분 | 화면에서 확인 |
| 뉴스가 전부 실패한 사이클이 `OK` 로 기록됨 | 뉴스가 없으면 AI 를 요청하지 않아 실패로 잡히지 않음 | `NEWS_FAILED` 결론 추가 | 로컬 실행에서 발견 (전용 테스트는 아직 없음) |

## 8. 남은 과제와 한계
- 수집 주소가 공식 Open API 가 아니다. 공식 전환 후보(공공데이터포털 주식시세정보 등)는 조사만 했다.
- 뉴스 관련성: 다른 종목이 주인공인 기사가 섞인다.
- Spring Boot 4.x 전환.
- Vercel → 백엔드 구간이 평문 HTTP 다. 백엔드 HTTPS 적용 필요.
- 운영 모델 교체 결정: 실험 결과를 바탕으로 정하되, GPT 측정과 표본 확대가 남아 있다.
- 실행 이력 표본이 작다. 오래된 이력 정리 로직도 없다.
- 네이버 검색 API 가 다른 플랫폼으로 이관 중이다. 사용 중인 키의 발급처와 약관(AI 활용 제한 여부) 확인 필요.
- 작업 중 대화에 노출된 DB 비밀번호·API 키는 교체해야 한다.

## 10. 발표에서 조심할 표현
- "gpt-6-luna 가 OpenAI 최저가"는 틀리다. 이전 세대 `gpt-5-nano` 가 더 싸다. "최신 세대 중 최저가"로 한정한다. 그리고 GPT 는 아직 측정하지 못했다.
- 실험은 모델당 3회, 입력 하나다. "가장 우수하다"가 아니라 "이 조건에서 이렇게 측정됐다"로 말한다.
- Gemma 의 결과는 "Gemini API 의 무료 등급으로 호출했을 때"의 것이다. 자체 서버에 설치했을 때의 성능이 아니다.
- 국산 모델의 "국내 데이터 처리"는 HyperCLOVA X 의 지원 리전이 "한국"이라는 것까지만 확인했다.
- 가격과 종료 일정은 2026-11-18 에 공식 페이지를 요약 도구로 읽은 값이다. 발표 직전에 원문을 열어 대조한다.
- 이 프로젝트는 AI 도구(Claude Code)를 써서 만들었다. 본인이 한 일(문제 정의, 판단, 서버 구성, 키 관리, 검증 확인)과 도구가 한 일을 구분해 말한다.
